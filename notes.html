Bootcamp Notes

Everything I've learned building the HR dashboard, plus the bugs I hit along the way.

HTML

Page skeleton & loading scripts 
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Page name</title>
    <link rel="stylesheet" href="styles.css">
    <script src="app.js" defer></script>
  </head>
  <body>…</body>
</html>
  • lang tells screen readers which language to pronounce.
  • viewport makes phones use their real width instead of zooming out.
  • defer downloads the script now but runs it after the HTML is parsed, so querySelector can find elements. Deferred scripts run in the order they're listed.
  • A <script src="…"> ignores any code written between its tags.
  • CSS is not loaded unless there's a <link rel="stylesheet"> in the <head>.
Semantic landmarks & headings
  • <header>, <nav>, <main> (one per page), <aside>, <section>, <article>, <footer>. Screen readers can jump between them; <div>/<span> mean nothing.
  • Two <nav>s on a page? Give each an aria-label ("Main", "Sections").
  • Name a section with aria-labelledby="id-of-its-heading". The id must match exactly.
  • One <h1>; then h2 → h3 in order, no skipping levels.
Forms
  • <label for="x"> ↔ <input id="x"> links them. Clicking the label focuses the input. Or wrap: <label><input> Text</label>.
  • A placeholder is not a label (it vanishes when typing). If there's no visible label, use a .visually-hidden one.
  • name="…" is the key FormData uses: new FormData(form).get('fullName').
  • Built-in validation: required, type="email", min/max/step, maxlength. The browser blocks submit until they pass.
  • Radios with the same name form one group. Name the group with <fieldset> + <legend>.
  • autocomplete takes tokens (name, email, tel, off), not example values.
  • method: GET puts data in the URL, POST in the request body. action="#" stays on the page.
Buttons: always set type
  • A <button> defaults to type="submit". Any non-submit button should be type="button".
  • type="reset" clears the whole form.
  • disabled blocks clicks. It's a UX nicety, not security (anyone can re-enable it in DevTools).
  • ⚠️ Never give a form control id/name of "submit" or "reset". It replaces form.submit()/form.reset(), causing "form.reset is not a function".
Tables 
<table>
  <caption>October 2026 pay run</caption>
  <thead><tr><th scope="col">Name</th>…</tr></thead>
  <tbody><tr><td>Priya</td>…</tr></tbody>
</table>
  • <caption> is the table's title.
  • <th scope="col"> is a header cell for its column. <td> is a data cell. Don't use th for data.
  • Render rows into the <tbody> only, so the caption and header survive.
  • Clickable header? Put a <button> inside the <th> so keyboards can reach it.

The cascade & specificity
  • When two rules set the same property: higher specificity wins. #id > .class / [attr] / :pseudo > tag.
  • Equal specificity → the rule later in the file wins. That's why h2 { margin-top: 2rem } must come after h1, h2, h3 { margin: 0 0 .5rem }.
  • Shorthands reset everything they cover: margin: 0 0 1rem also sets top to 0.
  • In DevTools → Styles, a losing declaration is shown crossed out.
Box model & box-sizing

Content → padding → border → margin (margin is outside and doesn't count toward width).

width: 300px; padding: 20px; border: 2px solid;

  • content-box (default): width = content only → 344px rendered (300 + 40 + 4).
  • border-box: width includes padding + border → 300px rendered, content shrinks to 256.
*, *::before, *::after { box-sizing: border-box; }

Check with DevTools → Computed (the box diagram) or el.offsetWidth.

Units: rem, em, px, %, vh, fr
  • rem is relative to the root (<html>) font size, 16px by default. 1.5rem = 24px. Scales with the user's browser font setting (accessibility).
  • em is relative to the element's own font size. Good for button padding that should grow with its text.
  • % is relative to the parent. vh = 1% of the window height. fr = a share of the leftover grid space.
  • Rule of thumb: rem for most spacing, em for things that should scale with their own text.
Margins: defaults & collapsing
  • Browsers give body, p, h1–h6, ul default margins. A <p> inside a padded footer adds its own 1em above and below.
  • Vertical margins collapse: between two stacked siblings, the bigger margin wins. They don't add up.
  • Space outside = margin. Space inside (where the background shows) = padding.
  • Margin 0 auto centres a block that has a width.
Invalid CSS fails silently
  • font-weight: 1500 is out of range (1–1000), so the whole line is ignored.
  • rgb(146, 146, 146 / 0.5) mixes comma and slash syntax, so it's ignored. Use rgb(146 146 146 / 0.5) (modern) or rgba(146, 146, 146, 0.5).
  • outline: 1px has no style, so it's invisible. You need outline: 2px solid color.
  • A typo in a selector (.siderbar) just matches nothing.
  • Always check DevTools → Styles for crossed-out lines with ⚠️.
Colour contrast
  • WCAG minimum: 4.5:1 for normal text, 3:1 for large text.
  • Semi-transparent grey text usually fails. Prefer a solid mid-grey like #6b7085.
  • DevTools: click the colour swatch next to color to see the ratio.
Flexbox (one direction) 
.toolbar { display: flex; align-items: center; gap: .75rem; }
  • On the container: flex-direction (row/column), justify-content (main axis: space-between…), align-items (cross axis: center), gap, flex-wrap: wrap.
  • On items: flex: 1 = take all spare room. flex: 1 1 240px = grow, shrink, aim for 240px (with wrap → responsive cards with no media queries). flex-shrink: 0 = never squash (avatars).
  • margin-left: auto pushes an item to the far right.
  • margin-top: auto inside a column pushes the item to the bottom.
  • ⚠️ Famous gotcha: flex items default to min-width: auto (never narrower than their content). To truncate text inside a flex child, give that child min-width: 0.
Truncate with an ellipsis (…) 
.name {
  white-space: nowrap;      /* one line */
  overflow: hidden;         /* hide the rest */
  text-overflow: ellipsis;  /* show … */
}
/* + min-width: 0 on the flex child that contains it */

All three lines are needed. Text-overflow only works on one line with hidden overflow.

Grid (rows and columns) 
.app {
  display: grid;
  grid-template-columns: 220px 1fr;
  grid-template-rows: 64px 1fr;
  grid-template-areas:
    "header  header"
    "sidebar main";
  min-height: 100vh;
}
.site-header { grid-area: header; }
  • Flex = one direction. Grid = two directions.
  • 1fr = one share of the leftover space.
  • Items without a grid-area get auto-placed into the next empty cell.
Custom properties (CSS variables) 
.progress__fill { width: var(--progress, 0%); }   /* 0% = fallback */
fill.style.setProperty('--progress', `${percent}%`);  // JS sets it
  • Names start with --. Read with var().
  • The clean way to pass a number from JS to CSS. Remember the unit (%).
  • transition: width .2s ease animates the change.

JavaScript basics

let, const & block scope
  • const can't be reassigned (but an object's contents can change). let can be reassigned. Avoid var.
  • Both are block-scoped: they only exist inside the { } where they're declared. A variable made inside a submit handler doesn't exist outside it.
  • Assigning without const/let (total = 0) creates an accidental global. Always declare.
  • Reassigning a const → TypeError: Assignment to constant variable. Make a new variable with a new name instead.
= vs === 
dir = 'desc';     // ASSIGNS: makes dir 'desc'
dir === 'desc';   // COMPARES: true/false, changes nothing

A line like state.dir === 'desc'; on its own does nothing at all.

for...of vs for...in 
for (const e of employees) { … }  // e = each ITEM (employee object)
for (const i in employees) { … }  // i = each KEY ('0', '1', '2' as strings)
  • of → items of an iterable: arrays, Sets, strings.
  • in → keys of an object.
  • for...of does not work on plain objects ("is not iterable").
Handy syntax: template literals, ternary, destructuring 
`Selected: ${count}`                       // template literal
dir === 'asc' ? 'desc' : 'asc'             // ternary = one-line if/else
const { key, dir } = state.tableSort;      // destructuring
a[key]                                     // bracket notation: property named by a variable
!checked                                   // flip a boolean
value || 0                                 // default if value is falsy

Falsy values: false, 0, '', null, undefined, NaN. Everything else is truthy.

Spread ... (unpack a collection) 
[...employees]                 // copy an array
[...new Set(list)]             // Set → array (unique values)
Math.max(...ids)               // array → separate arguments
{ ...emp, salary: 190000 }     // copy an object, change one field
el.replaceChildren(...nodes)   // array of elements → arguments
  • Array(mySet) does not unpack. It makes [Set], one item.
  • Math.max([1,2,3]) is NaN. Math.max(...[1,2,3]) is 3.

Sorting: compare functions 
(a, b) => a.name.localeCompare(b.name)    // strings, A–Z
(a, b) => a.salary - b.salary             // numbers, low → high
(a, b) => b.salary - a.salary             // swapped = high → low
return dir === 'asc' ? result : -result;  // flip sign = reverse
  • Return negative → a first; positive → b first; 0 → equal.
  • Store numbers as numbers. As strings, '$80,000' sorts after '$145,000'.
  • 'YYYY-MM-DD' date strings sort correctly as strings.
  • typeof x === 'number' to choose between the two.
Set: unique values 
const depts = new Set();
for (const e of employees) depts.add(e.dept);   // duplicates ignored
const sorted = [...depts].sort();               // Set has no .sort()
Closures

A function "remembers" the variables from where it was created. Each Remove button's listener, created inside the submit handler, remembers its own li:

const li = document.createElement('li');
removeBtn.addEventListener('click', () => li.remove());

DOM & events

Finding elements 
document.querySelector('#agree')        // first match, or null
document.querySelectorAll('.card')      // all matches (has forEach)
el.closest('tbody tr')                  // walk UP to the nearest match, or null
  • It takes a CSS selector: 'agree' looks for an <agree> tag, '.dept' for a class, '#dept' for an id.
  • Wrong selector → null → "Cannot read properties of null" on the next line.
  • Call it on an element to search only inside it: form.querySelector('input').
textContent vs innerHTML (XSS)
  • textContent = plain text, never parsed. Safe by default.
  • innerHTML = parses the string as HTML. Putting user data in it without escaping = XSS (a name like <img src=x onerror=alert(1)> would run code).
  • With innerHTML, run every piece of data through escapeHTML().
  • Setting textContent replaces everything inside, child elements too. Set text before appending children.
Creating & changing elements 
const li = document.createElement('li');  // create (in memory)
li.textContent = 'New hire';              // fill
list.append(li);                          // put on the page (at the end)
li.remove();                              // take it off
listEl.replaceChildren(...cards);         // clear + insert in one go
  • A string like `<option>…</option>` is not an element. append would add it as text.
  • You can't assign elements to innerHTML (you'd see [object HTMLElement]).
classList, attributes & dataset 
el.classList.add('x')     el.classList.remove('x')
el.classList.toggle('x')  // returns true if now present
el.classList.contains('x')
el.setAttribute('aria-sort', 'ascending');  el.removeAttribute('aria-sort');
el.dataset.id      // reads data-id="…" (always a STRING, so use Number())
el.dataset.id = 5  // writes data-id="5"
input.value  checkbox.checked  button.disabled
  • classList = only that element's own classes ("sticky notes" on it), not its parents'.
  • el.className = 'x' replaces all classes; classList changes one.
The DOM vs the HTML file
  • The browser builds a live copy of the page in memory (the DOM). JS changes the DOM, never your file.
  • DevTools → Elements = live DOM (shows is-selected, generated cards). View Source (Cmd+Opt+U) = the original file.
  • Refreshing rebuilds the DOM from the file, so all JS changes are lost (use localStorage to remember things).
Events you'll use
EventFires when
clickclicked (or Enter/Space on a button)
inputevery keystroke/paste/delete
changeselect picked, checkbox ticked, text field loses focus
submitform submitted, after built-in validation passes
resetform reset. Fires before the fields clear.
keydowna key is pressed (event.key)
  • The first argument is an event name. There's no 'checkbox' event; it silently never fires.
  • form.reset() does not fire input/change, so reset counters and buttons in a reset listener.
  • event.preventDefault() on submit stops the page reload.
Bubbling & event delegation

A click starts at the innermost element and bubbles up: td → tr → tbody → table. Every ancestor's click listener runs.

list.addEventListener('click', (e) => {
  const btn = e.target.closest('[data-action="remove"]');
  if (!btn) return;            // click wasn't on a Remove button
  …
});
  • Delegation = one listener on the parent handles all children, including ones rendered later.
  • event.target = what was clicked. event.currentTarget = what the listener is on.
  • ⚠️ Two listeners that both toggle the same class cancel each other out (row-selection bug).
  • ⚠️ A listener on a parent hears every child. Check event.target (the radio-button bug).

Patterns

State → render() 
const state = { employees: [...], query: '', dept: 'All' };

function render() { /* read state, redraw the page */ }

search.addEventListener('input', (e) => {
  state.query = e.target.value;   // 1. update state
  render();                       // 2. redraw
});
  • Handlers only change state, then call render(). Never patch the page by hand.
  • Helpers like getVisible() read state and return a new array without changing anything.
  • Things that run once (building dropdown options) go outside render().
  • Containers that render() fills must be empty in the HTML. Anything else inside gets wiped.
  • This is how React works.
Single source of truth
  • Recount from the page/data (querySelectorAll(…).length) instead of keeping a separate counter that can drift.
  • Store raw data (115000), format when displaying (formatSalary).
  • Build UI from data (department options via new Set) so it updates itself when data changes. Test: add a "Finance" employee and it appears.
  • Unique ids: Math.max(...list.map((e) => e.id)) + 1.
JS sets state, CSS owns the visuals
  • Toggle a class (is-selected, compact) and let CSS style it. Avoid el.style.color = ….
  • Set an attribute (aria-sort) and let CSS draw from it: th[aria-sort="ascending"] button::after { content: " ▲"; }.
  • For numbers, set a CSS variable (--progress).
Template string vs createElement (tradeoff)
Template + innerHTMLcreateElement + textContent
SafetyMust escape every value. Forget once = XSS.Safe by default.
LengthShort, looks like the HTML.Verbose (about 3× the lines).
ResultA string the browser parses.Real elements you can keep and attach listeners to.

Interview line: "innerHTML is concise but you have to remember to escape; createElement is safe without trying, at the cost of verbosity. React's JSX gives you both."

Debugging

How to debug: Console first
  1. Open the Console (Cmd+Opt+J) and refresh.
  2. Fix the first red error, refresh, repeat. JS stops at the first crash.
  3. If lots of unrelated things break at once, it's usually one early crash: everything after it (including listeners) never runs.
  4. A syntax error (e.g. HTML written in JS without quotes) stops the whole file from running.
  5. Use console.log(state) to check data before blaming the UI.
  6. Hard refresh with Cmd+Shift+R if changes don't show.

DevTools tips
  • Elements: the live DOM. Watch classes and attributes change as you click.
  • Styles: crossed-out = lost the cascade; ⚠️ = invalid value. Edit live to experiment (lost on refresh).
  • Computed: the box-model diagram (content / padding / border / margin).
  • Hover an element: orange = margin, green = padding.
  • Device toolbar (Cmd+Shift+M) to test phone widths.
  • Run a local server when you need it: python3 -m http.server 8000 → localhost:8000.
