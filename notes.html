    Document basics

    Page skeleton 
    <!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Page name</title>
    <meta name="description" content="Shown in search results">
    <link rel="stylesheet" href="styles.css">
    <script src="app.js" defer></script>
  </head>
  <body> …visible content… </body>
</html>
    • <!DOCTYPE html>: use modern standards mode (without it, browsers use "quirks mode").
    • lang: the page language, so screen readers pronounce it correctly and translators know what it is.
    • charset: UTF-8 covers every language and symbol.
    • viewport: makes phones use their real width instead of a zoomed-out 980px desktop view.
    • <head> = information about the page (not shown). <body> = everything visible.
    Loading scripts: plain vs defer vs async vs module
    TagDownloadsRuns
    <script src>blocks parsingimmediately, before the rest of the HTML exists
    deferin parallelafter the HTML is parsed, in order
    asyncin parallelas soon as it's downloaded, in any order
    type="module"in paralleldeferred by default; allows import/export
    • A script with src ignores any code between its tags.
    • Without defer, put scripts at the end of <body> or querySelector returns null.
    Three ways to add CSS
    • External (best): <link rel="stylesheet" href="styles.css"> in the head. Cached and shared between pages.
    • Internal: a <style> block in the head. Fine for one page.
    • Inline: style="color: red" on an element. Highest specificity, hard to maintain; avoid.
    Elements, tags, attributes, nesting
    • An element = opening tag + content + closing tag: <p>Hello</p>.
    • Void (self-closing) elements have no content or closing tag: img, input, br, hr, meta, link.
    • Attributes go in the opening tag, separated by spaces: <a href="/" class="logo">.
    • Boolean attributes are on just by being present: required, disabled, checked, hidden. (disabled="false" is still disabled!)
    • Close tags in reverse order of opening. A missing > swallows the next tag.
    • Comments: <!-- like this -->.

    &quot;"inside attribute values
    &nbsp;(space)non-breaking space: keeps two words on one line

    id vs class

    An id is unique on the page (one element); a class can be reused on many elements, and an element can have several classes.

    • Use ids for things that must be found exactly once: for="" labels, aria-labelledby, anchor links (#section), getElementById.
    • Use classes for styling and for groups of elements.
    • CSS: #id has much higher specificity than .class, which is one reason to style with classes.
    • An id or name on a form control becomes a property of the form, so id="reset" breaks form.reset().
    Global attributes worth knowing
    • id, class, style, title (tooltip; not reliable for accessibility).
    • hidden: not displayed and hidden from screen readers.
    • data-*: your own data, read in JS with el.dataset.
    • tabindex: 0 = focusable in normal order, -1 = focusable only by JS, positive = avoid.
    • lang, dir (text direction), contenteditable, draggable.
    • aria-* and role: accessibility information.

    CSS can change this with display. img, input and button are technically inline but accept width/height (they're "replaced"/inline-block-like).

    div vs span

    Both have no meaning. div is a block container; span is an inline container for a bit of text.

    Use them only when no semantic element fits, usually as hooks for styling or layout.

    Semantic layout elements

    Landmarks at a glance
    ElementMeaningRules of thumb
    <header>Introductory content: logo, title, top navCan be used for the page or inside an article/section
    <nav>Major navigation linksNot every group of links. Label it if there's more than one
    <main>The main content of the pageExactly one, not inside header/footer/aside
    <section>A themed group of contentShould have a heading
    <article>Self-contained, makes sense on its ownBlog post, card, comment, product
    <aside>Related but secondary contentSidebar, callout, "related links"
    <footer>Closing info: copyright, contact, linksFor the page or for an article/section
    <div>NothingStyling/layout hook only

    Screen reader users can list and jump between landmarks, so the right element is navigation for them.

    div vs section vs article

    article is self-contained and would make sense on its own; section groups related content under a heading; div means nothing and is just for styling.

    Test: could you share this piece on another site and it still makes sense? Then it's an article. Does it have a natural heading? section. Only need a wrapper for CSS? div.

    div vs aside

    aside is content related to the page but not essential to it (a sidebar, tip or related links), and it's a landmark screen readers can jump to. A div has no meaning.

    If you deleted it and the main content still made complete sense, it's probably an aside.

    section vs main

    main is the single primary content area of the page; sections are the parts inside it (or elsewhere).

    header vs head vs h1
    • <head>: the invisible metadata part of the document.
    • <header>: a visible introductory area (often the site banner).
    • <h1>: the main heading text.
    figure, figcaption, time, address
    • <figure> + <figcaption>: an image, chart or code sample with a caption.
    • <time datetime="2026-10-20">Oct 20</time>: a human date with a machine-readable value.
    • <address>: contact information for the page or article author.

    Text

    Headings
    • h1–h6 describe structure, not size. Style the size with CSS.
    • One h1 per page, then don't skip levels (h2 → h4).
    • Screen reader users navigate by headings more than anything else.
    strong vs b, em vs i

    strong and em add meaning (importance and emphasis, which screen readers can convey); b and i are only visual styling with no extra meaning.

    <i> is still fine for things like foreign words or ship names; <b> for keywords that should stand out without being "important".

    Other text elements
    ElementUse
    pA paragraph
    brA line break inside content (addresses, poems). Not for spacing
    hrA thematic break between sections
    smallSide comments, fine print
    markHighlighted text (e.g. search matches)
    code / preInline code / preformatted block that keeps whitespace
    kbdKeyboard keys
    blockquote / q / citeBlock quote / inline quote / title of a work
    abbr title="…"Abbreviation with its expansion
    sub / supSubscript (H₂O) / superscript (x²)
    Lists: ul vs ol vs dl
    • <ul>: unordered (order doesn't matter). Navigation menus are usually a ul.
    • <ol>: ordered (steps, rankings). Attributes: start, reversed.
    • <dl> with <dt> (term) and <dd> (description): glossaries, key/value details.
    • Only <li> can be a direct child of ul/ol.
    • Screen readers announce "list, 3 items", which helps users.

    Links & media

    Links
    • Absolute href="https://site.com/page", relative href="about.html" / "../img/x.png", root-relative href="/about".
    • Same page: href="#payroll" jumps to id="payroll".
    • mailto: and tel: open email/phone apps.
    • target="_blank" opens a new tab. Add rel="noopener" for older browsers, and warn users.
    • Link text should make sense on its own. Avoid "click here".
    • download attribute makes the link download the file.
    button vs a (link)

    A link goes somewhere (navigation); a button does something on the page (an action).

    They behave differently for keyboards (Enter only vs Enter and Space) and screen readers announce them differently.

    Images 
    <img src="photo.jpg" alt="Priya smiling at her desk"
     width="120" height="120" loading="lazy">
    • alt is required. Describe what matters in context; alt="" for decorative images.
    • width/height reserve space so the page doesn't jump while loading.
    • loading="lazy": only load when near the screen.
    • srcset/sizes or <picture>: different files for different screen sizes/formats.
    • Decorative images are often better as CSS background-image.
    Video, audio, iframe
    • <video src controls> / <audio src controls>. controls shows play buttons. Add <track kind="captions"> for captions.
    • <iframe src title="…"> embeds another page (maps, YouTube). Always give it a title.

    Tables

    Table structure 
    <table>
  <caption>October pay run</caption>
  <thead>
    <tr><th scope="col">Name</th><th scope="col">Salary</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">Priya</th><td>$115,000</td></tr>
  </tbody>
  <tfoot> …totals… </tfoot>
</table>
    • caption = title. thead/tbody/tfoot = header, body, footer row groups.
    • th = header cell (with scope="col" or "row"); td = data cell.
    • colspan="2" / rowspan="2" merge cells.
    • Tables are for tabular data only, never for page layout (use grid/flex).

    Forms

    The form element
    • action: where to send the data (default: the current page).
    • method: get (data in the URL; for searches) or post (data in the body; for creating/changing things).
    • Submitting reloads the page unless JS calls event.preventDefault().
    • novalidate turns off built-in validation.
    Input types
    typeGives you
    textPlain text (default)
    email, url, telValidation (email/url) and the right phone keyboard
    numberNumber spinner; min, max, step
    passwordHidden characters
    searchClear (×) button, search keyboard
    date, time, datetime-localPickers; value is always YYYY-MM-DD
    checkbox, radioOn/off; one-of-many (same name = one group)
    range, color, fileSlider, colour picker, file chooser (accept="image/*")
    hiddenA value sent with the form but not shown
    Labels 
    <label for="email">Work email</label>
<input id="email" name="email" type="email">

<label><input type="checkbox" name="agree"> I agree</label>
    • Every input needs a label: for matches the input's id, or wrap the input.
    • Clicking the label focuses/toggles the input (bigger click target).
    • A placeholder is not a label.
    • name is the key the data is submitted (and read by FormData) under.
    select, textarea, fieldset, datalist
    • <select> with <option value="x">; group options with <optgroup label>; multiple allows several.
    • An option without value uses its text as the value.
    • <textarea rows="4" maxlength="200">: multi-line text.
    • <fieldset> + <legend>: group related fields (radio groups especially).
    • <datalist>: suggestions for a text input (list="id").
    Buttons
    • type="submit" (the default!), type="reset", type="button".
    • Always write the type. A plain button inside a form will otherwise submit it.
    • <button> can contain HTML (icons); <input type="submit" value> can't.
    Built-in validation attributes
    • required, min/max, step, minlength/maxlength, pattern="[A-Z]{3}" (regex), and the input type.
    • The browser blocks submit and shows a message; the submit event only fires once everything passes.
    • CSS hooks: :invalid, :valid, :required, :user-invalid.
    • Client-side validation is for UX. Servers must check again.
    autocomplete

    Takes tokens that tell the browser what to auto-fill: name, email, tel, street-address, new-password, current-password, off. Not example values (those go in placeholder).

    Accessibility

    The basics checklist
    • Semantic elements and landmarks; one h1; headings in order.
    • Every image has alt; every input has a label.
    • Real buttons and links, never clickable divs.
    • Everything works with a keyboard, with a visible focus style.
    • Colour contrast at least 4.5:1 (3:1 for large text); don't rely on colour alone.
    • lang on <html>; descriptive link text; captions for video.
    ARIA cheat sheet
    AttributeUse it for
    aria-labelA name as a string, for elements with no visible text (icon buttons) or to make repeated buttons unique
    aria-labelledbyA name taken from another element's text, by id
    aria-describedbyExtra description read after the name (hints, counters, errors)
    aria-live="polite" / role="status"Announce text changes without moving focus
    role="alert"Announce urgent errors immediately
    aria-current="page"The link to the current page
    aria-pressedToggle button state
    aria-expandedWhether a menu/accordion it controls is open
    aria-controlsWhich element this one controls (by id)
    aria-selectedThe chosen tab/option
    aria-sortSorted table column: ascending/descending
    aria-hidden="true"Hide decorative things from screen readers (never on focusable elements)
    aria-invalidA field that failed validation

    First rule of ARIA: if a native element does the job, use it. ARIA changes what's announced, not how it behaves.

    Focus and tabindex
    • Links, buttons and form fields are focusable automatically.
    • tabindex="0": add a custom element to the Tab order. tabindex="-1": focusable only with el.focus() (e.g. moving focus to a heading or dialog).
    • Never use positive tabindex; it breaks the natural order.
    • Use :focus-visible to style keyboard focus without showing it on mouse clicks.
    Visually hidden vs hidden
    • .visually-hidden class: invisible but still read by screen readers (e.g. a label for a search box).
    • hidden / display: none: hidden from everyone.
    • aria-hidden="true": visible but ignored by screen readers.

    details / summary

    A disclosure widget (accordion) with no JS: clicking the summary opens and closes it. open attribute = expanded. These notes are built with it.

    <dialog id="modal"> … </dialog>

    <progress value="40" max="100"> for task progress; <meter> for a measurement in a range (disk usage). Both are accessible out of the box.

    Cascade, specificity, inheritance

    How conflicts are decided
    1. Importance: !important wins (avoid it).
    2. Specificity: inline style > #id > .class / [attr] / :pseudo-class > element / ::pseudo-element.
    3. Order: equal specificity → the later rule wins.

    Count specificity as (ids, classes, elements): #nav .link a = (1, 1, 1) beats .nav .link a = (0, 2, 1). * and combinators add nothing.

    Inheritance
    • Text properties inherit to children: color, font-*, line-height, text-align, letter-spacing, visibility, cursor, list-style.
    • Box properties don't: margin, padding, border, width, background, display, position.
    • Form controls don't inherit fonts by default, so add font: inherit.
    • Keywords: inherit (take the parent's value), initial (the spec default), unset (inherit if inheritable, else initial), all: unset (reset everything).
    • A direct rule always beats an inherited value, whatever the specificity of the parent's rule.
    Shorthands
    • margin: 10px (all) · 10px 20px (top/bottom, left/right) · 10px 20px 30px (top, sides, bottom) · 10px 20px 30px 40px (top, right, bottom, left: clockwise).
    • Same pattern for padding, border-width, inset.
    • border: 1px solid #ccc, font: 600 1rem/1.5 system-ui, background, flex, grid-area.
    • A shorthand resets every sub-property it covers, even ones you didn't write.
    • Logical properties: margin-inline (left+right), margin-block (top+bottom).

    Box model

    The box model and box-sizing

    Every element: content → padding (inside, shows the background) → border → margin (outside, transparent).

    width: 300px; padding: 20px; border: 2px solid

    • content-box (default): width = content only → 344px on screen.
    • border-box: width includes padding and border → 300px on screen (content shrinks to 256).
    *, *::before, *::after { box-sizing: border-box; }
    margin vs padding

    Padding is space inside the border (it gets the background and is part of the click area); margin is space outside the border that pushes other elements away.

    • Margins can be negative and auto; padding can't.
    • Vertical margins collapse; padding never does.
    Margin collapsing
    • When two block elements stack, the gap is the larger of the bottom and top margins, not the sum.
    • A child's top margin can "leak" out through a parent with no padding/border.
    • Doesn't happen with padding/borders in between, inside flex or grid containers, or horizontally.
    border vs outline

    A border takes up space and affects layout; an outline is drawn outside the box without taking space (used for focus rings). Both need a style: outline: 2px solid, not just outline: 2px.

    width, height, min/max
    • max-width: 1100px; margin: 0 auto: a centred container that shrinks on small screens.
    • min-height: 100vh: at least the window's height but can grow.
    • Avoid fixed height on text containers; content overflows.
    • aspect-ratio: 16 / 9 keeps proportions.
    overflow
    • visible (default: spills out), hidden (clipped), scroll (always scrollbars), auto (scrollbars only when needed).
    • overflow-x: auto on wide tables/code so the page doesn't scroll sideways on phones.
    • overflow: hidden on a rounded parent clips its children to the corners.

    Text & decoration

    Typography properties
    • font-family: system-ui, sans-serif (a stack: first available wins; end with a generic family).
    • font-size, font-weight (100–900 typical; 400 normal, 700 bold; valid range 1–1000), font-style: italic.
    • line-height: 1.5 (unitless), letter-spacing, text-transform: uppercase.
    • text-align, text-decoration: none (remove link underline), text-indent.
    • font-variant-numeric: tabular-nums: equal-width digits for tables.
    • Load web fonts with Google Fonts <link> or @font-face.
    white-space and truncation 
    .name {
  white-space: nowrap;      /* one line */
  overflow: hidden;         /* clip the rest */
  text-overflow: ellipsis;  /* show … */
}
    • All three are needed. Inside a flex child, that child also needs min-width: 0.
    • Multi-line: -webkit-line-clamp: 2 with display: -webkit-box; -webkit-box-orient: vertical; overflow: hidden.
    • overflow-wrap: anywhere breaks very long words/URLs.
    Backgrounds, borders, shadows
    • background-color, background-image: url() / linear-gradient(…), background-size: cover, background-position: center.
    • border-radius: 12px; 50% on a square = circle; 999px = pill.
    • box-shadow: x y blur spread color, e.g. 0 1px 3px rgb(0 0 0 / 10%); inset for inner shadows.
    • text-shadow for text.

    Flexbox

    Flexbox container properties
    • display: flex: children become flex items in a row.
    • flex-direction: row (default) or column. This sets the main axis; the other one is the cross axis.
    • justify-content (main axis): flex-start, center, flex-end, space-between, space-around, space-evenly.
    • align-items (cross axis): stretch (default), center, flex-start, flex-end, baseline.
    • flex-wrap: wrap: let items move to new lines. align-content spaces those lines.
    • gap: 1rem: space between items only.
    Flexbox item properties
    • flex: grow shrink basis. flex: 1 = take an equal share of spare space. flex: 1 1 240px = aim for 240px, grow and shrink.
    • flex-shrink: 0: never shrink (avatars, icons).
    • align-self: override align-items for one item.
    • order: visual order (doesn't change tab/reading order, so use carefully).
    • margin-left: auto: push this item (and everything after it) to the end.
    • ⚠️ Items default to min-width: auto (never narrower than their content). Text truncation inside needs min-width: 0.
    Common flex recipes 
    /* navbar: logo left, links right */
.header { display: flex; justify-content: space-between; align-items: center; }

/* toolbar: search grows, button pushed right */
.toolbar { display: flex; gap: .75rem; }
.toolbar input { flex: 1; }
.toolbar .btn { margin-left: auto; }

/* responsive card row, no media queries */
.cards { display: flex; flex-wrap: wrap; gap: 1.5rem; }
.card { flex: 1 1 240px; }

/* card with button pinned to the bottom */
.card { display: flex; flex-direction: column; }
.card .btn { margin-top: auto; }

    Grid

    Grid basics 
    .app {
  display: grid;
  grid-template-columns: 220px 1fr;
  grid-template-rows: 64px 1fr;
  grid-template-areas:
    "header  header"
    "sidebar main";
  gap: 1rem;
}
.site-header { grid-area: header; }
    • fr = one share of the leftover space.
    • grid-template-areas draws the layout with names; place items with grid-area.
    • Or place by line numbers: grid-column: 1 / 3 or grid-column: span 2.
    • Items without a placement are auto-placed into the next empty cell.
    repeat, minmax, auto-fit 
    grid-template-columns: repeat(3, 1fr);                        /* 3 equal columns */
grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));  /* as many as fit */

    The auto-fit + minmax line makes a responsive card grid with no media queries.

    Alignment in grid
    • justify-items (inline/row axis) and align-items (block/column axis) align items inside their cells.
    • place-items: center = both at once.
    • justify-content / align-content align the whole grid inside its container.
    • justify-self / align-self for one item.

    Flex vs grid

    Flexbox vs Grid
    FlexboxGrid
    DimensionsOne: a row or a columnTwo: rows and columns
    Driven byContent (items size themselves)Layout (you define the tracks)
    Alignment across rowsEach wrapped line is independentColumns line up across rows
    Best forNavbars, toolbars, button groups, a single row of cards, centringPage layouts, dashboards, galleries, forms that line up

    Flexbox for laying things out in one direction; grid when you need rows and columns to line up. They're often combined: grid for the page, flex inside the pieces.

    Centring, every way 
    .parent { display: grid; place-items: center; }

.parent { display: flex; justify-content: center; align-items: center; }

.child { margin: 0 auto; width: 600px; }      /* horizontal, block */

.parent { text-align: center; }               /* inline content */

.child { position: absolute; top: 50%; left: 50%;
         transform: translate(-50%, -50%); }  /* over something */

    Positioning & layering

    position values
    ValueIn normal flow?Positioned relative to
    staticYesNot positioned (default; top/left ignored)
    relativeYes (space kept)Its own normal spot. Also becomes the anchor for absolute children
    absoluteNoNearest positioned (non-static) ancestor
    fixedNoThe viewport (stays when scrolling)
    stickyYesNormal until it hits e.g. top: 0, then sticks inside its parent

    Classic pattern: parent position: relative, child position: absolute; top: 0; right: 0 for a badge in a corner. inset: 0 = all four sides 0.

    z-index and stacking contexts
    • z-index only works on positioned elements (and flex/grid items). Higher = in front.
    • A stacking context is a separate layer group. Created by e.g. position + z-index, opacity < 1, transform, filter.
    • A child can never appear above something outside its parent's stacking context, no matter how big its z-index.
    • Sticky toolbars need a background, or content shows through.
    Modal overlay recipe 
    .overlay {

    Scope
    • Global: top level of a classic script; visible to every script on the page.
    • Function: inside a function.

    • Function declarations are hoisted fully, so you can call them before they appear.

    • = assigns.
    • === compares value and type with no conversion. Always use this.

    Truthy and falsy

    Functions

    Declaration vs expression vs arrow 
    function add(a, b) { return a + b; }       // declaration (hoisted)

    • Arrow functions have no own this (they use the surrounding one) and no arguments.
    • Default parameters: function greet(name = 'there') { }.
    • A function without return returns undefined.
    • Functions are values: pass them as arguments (callbacks) and return them.
    Callbacks and higher-order functions

    A callback is a function you pass to another function to call later: addEventListener('click', handleClick), arr.map(toCard). A higher-order function takes or returns functions.

    Pass the function itself (map(cardEl)), don't call it (map(cardEl())).

    Closures 
    function counter() {
  let count = 0;
  return () => ++count;       // remembers count
}
const next = counter();
next(); next();               // 1, 2

    A function remembers the variables from where it was created. Used in event handlers, debounce, and private state.

    this (brief)
    • In a method call obj.fn(), this is obj.
    • In a regular-function event listener, this is the element (same as event.currentTarget).
    • Arrow functions take this from the surrounding code.
    • A plain function call: undefined in strict mode.

    What is the round?

    A 60-minute HackerRank "Web Fundamentals" exercise covering HTML, CSS and JavaScript.

    2. Get a working version of each requirement before polishing any of them.
    3. Run the tests early and often. Fix the first failing one.
    4. Keep the Console open. Fix the first red error.

    6. Last 10 minutes: edge cases (empty input, no matches, duplicates), accessibility, tidy up.

    HTML & accessibility questions

    What is semantic HTML and why does it matter?

    Using elements for their meaning (header, nav, main, button) instead of generic divs, so browsers, screen readers and search engines understand the page.

    Landmarks let screen reader users jump around; real buttons get keyboard support for free.

    div vs section vs article vs aside?

    article is self-contained; section groups related content under a heading; aside is related but secondary content like a sidebar; div has no meaning and is just for styling.

    button vs link?

    A link navigates somewhere; a button performs an action on the page.

    What is a button's default type?

    submit. Inside a form, a button without type="button" submits the form and reloads the page.

    How do you label a form input?

    A label whose for matches the input's id, or wrap the input in the label. A placeholder is not a label.

    No visible label? A visually-hidden label or aria-label. Group radios with fieldset + legend.

    What does defer do? defer vs async?

    defer downloads in parallel and runs after the HTML is parsed, in order; async runs as soon as it downloads, in any order.

    A plain script in the head runs before the body exists, so querySelector returns null.

    How do you write good alt text?

    Describe what the image conveys in context; use alt="" when it's decorative or the info is already in nearby text.

    aria-label vs aria-labelledby vs aria-describedby?

    aria-label gives a name as a string; aria-labelledby takes the name from another element by id; aria-describedby adds extra description read after the name.

    When should you use ARIA?

    Only when native HTML can't do it. The first rule of ARIA is to use a native element if one exists.

    How do you announce a status message to screen readers?

    Put it in an element with role="status" or aria-live="polite"; its changes are announced without moving focus.

    How do you hide something visually but keep it for screen readers?

    A visually-hidden class (1px, clipped, overflow hidden, absolutely positioned). display:none hides it from screen readers too.

    How do you make something keyboard accessible?

    Use native interactive elements so it's focusable and works with Enter/Space, and keep a visible focus style.

    Modals: move focus in, trap Tab, Escape closes, return focus to the opener.

    GET vs POST?

    GET puts data in the URL, for reading and searching; POST sends it in the body, for creating or changing data.

    CSS questions

    Explain the box model. content-box vs border-box?

    Content, padding, border, margin. With content-box, width is just the content; with border-box it includes padding and border.

    width 300 + padding 20 + border 2 → 344px vs 300px.

    How does specificity work?

    Inline styles beat ids, ids beat classes/attributes/pseudo-classes, those beat elements; if equal, the later rule wins. !important overrides all of it, so I avoid it.

    rem vs em vs px?

    px is fixed, rem is relative to the root font size, em is relative to the element's own font size. rem respects the user's font settings.

    Flexbox vs Grid?

    Flexbox is one-dimensional and content-driven; grid is two-dimensional and layout-driven. Grid for page structure, flex for components, often together.

    How do you centre a div?

    On the parent: display grid with place-items center, or display flex with justify-content and align-items center.

    Explain position: relative, absolute, fixed, sticky.

    relative stays in flow and anchors absolute children; absolute leaves the flow and positions against the nearest positioned ancestor; fixed is against the viewport; sticky scrolls normally until a threshold, then sticks.

    Why isn't my z-index working?

    z-index only applies to positioned (or flex/grid) elements, and only competes within the same stacking context.

    display:none vs visibility:hidden vs opacity:0?

    display none removes it from layout and screen readers; visibility hidden keeps its space but hides it from everyone; opacity 0 keeps space and is still clickable and read aloud.

    What is margin collapsing?

    Vertical margins between stacked blocks combine into the larger one instead of adding up. It doesn't happen in flex or grid containers.

    Pseudo-class vs pseudo-element?

    A pseudo-class selects a state, like :hover; a pseudo-element styles a part or adds content, like ::after.

    What is mobile-first?

    Base CSS targets small screens and min-width media queries add layout as space grows.

    Why won't my text truncate in a flex item?

    Flex items default to min-width: auto, so they won't shrink below their content. Set min-width: 0 on the flex child.

    JavaScript questions

    let vs const vs var?

    let and const are block-scoped, var is function-scoped. const can't be reassigned. I default to const, use let when reassigning, avoid var.

    == vs ===?

    === compares value and type with no conversion; == converts types first. I always use ===.

    What's truthy and falsy?

    Falsy: false, 0, empty string, null, undefined, NaN. Everything else is truthy, including empty arrays and objects.

    null vs undefined?

    undefined means never assigned; null means intentionally empty.

    map vs forEach vs filter vs reduce?

    map returns a transformed array, filter returns the items that pass, reduce boils it down to one value, and forEach just runs code and returns nothing.

    Does sort mutate? How do you sort numbers?

    Yes, it sorts in place, so I copy first. By default it compares as strings, so numbers need (a, b) => a - b.

    What is a closure?

    A function that remembers the variables from the scope where it was created, even after that scope has finished.

    Examples: event handlers remembering their item, debounce's timer, a counter.

    What is hoisting?

    Declarations are processed before code runs: function declarations are usable early, var is undefined early, let and const throw if used before their line.

    Arrow vs regular functions?

    Arrows are shorter and don't have their own this; they use the surrounding this.

    Primitive vs reference types?

    Primitives are copied by value; objects and arrays are shared by reference, so changing a "copy" changes the original unless you actually clone it.

    What does the spread operator do?

    Unpacks an array, Set or object into individual items, which is used for copies, merges and passing arrays as arguments. Copies are shallow.

    for...of vs for...in?

    for...of loops over values of an iterable; for...in loops over the keys of an object.

    DOM & events questions

    textContent vs innerHTML?

    textContent sets plain text and is safe; innerHTML parses HTML, so user data in it can cause XSS.

    What is XSS and how do you prevent it?

    Untrusted text gets parsed as HTML and runs script on your page. Insert data with textContent or createElement, or escape it before innerHTML.

    createElement vs template + innerHTML?

    innerHTML is concise but you must remember to escape; createElement is safe by default but more verbose.

    Why preventDefault on submit?

    The default submit sends the form and reloads the page; preventDefault lets JS handle it without losing state.

    event.target vs event.currentTarget?

    target is what was actually clicked; currentTarget is the element the listener is attached to.

    What is event bubbling?

    After an event fires on an element it travels up through its ancestors, triggering their listeners too.

    What is event delegation?

    One listener on a parent handles events from all its children using bubbling and closest. It covers items added later and avoids many listeners.

    input vs change event?

    input fires on every keystroke; change fires when the value is committed.

    Why toggle classes instead of setting styles?

    It keeps state in JS and visuals in CSS, so the design can change without touching the JS.

    Why would querySelector return null?

    The selector is wrong (missing # or ., typo), or the script ran before the element existed.

    How do you persist data in the browser?

    localStorage, which stores strings only, so JSON.stringify to save and JSON.parse to read.

    What is debouncing?

    Delaying a function until the user stops triggering it, e.g. searching only after typing pauses. It uses a closure to remember the timer.

    What is the state → render pattern?

    One state object holds what can change, one render function rebuilds the UI from it, and handlers only update state then call render.

    Async questions

    What is a Promise?

    An object for a value that arrives later: pending, then fulfilled with a value or rejected with an error.

    How does async/await work?

    An async function returns a promise; await pauses it until a promise settles, so async code reads top to bottom, with try/catch for errors.

    Does fetch throw on a 404?

    No, fetch only rejects on network failure, so you check res.ok yourself.

    What UI states does a fetch need?

    Loading, success, empty and error, ideally with a retry.

    What order does this log? (1, setTimeout 2, Promise 3, 4)

    1, 4, 3, 2: synchronous code first, then microtasks like promises, then macrotasks like setTimeout.

    How do you run requests in parallel?

    Promise.all, which resolves when all succeed and rejects on the first failure; allSettled waits for every one.

    React questions

    What is React?

    A library where you describe UI as a function of state; when state changes React re-renders and updates only what changed in the DOM.

    Props vs state?

    Props are read-only inputs from the parent; state is data a component owns and changes, which triggers a re-render.

    Why do lists need keys?

    Keys let React match items between renders. Use a stable id; index keys break when items are reordered or removed.

    Why not mutate state?

    React compares references to detect changes, so mutating the same array looks like no change. Always create a new array or object.

    What is useEffect for?

    Side effects after render, like fetching or timers. The dependency array controls when it re-runs, and it can return a cleanup.

    What is a controlled input?

    An input whose value comes from state and updates state on every change.

    Is JSX safe from XSS?

    Text in curly braces is escaped automatically; dangerouslySetInnerHTML is not.

    Gotchas (bugs I actually hit)

    JavaScript gotchas
    • x === 'desc'; compares and does nothing. Assignment is =.
    • for (e in arr) gives indexes; an undeclared e becomes a global.
    • Array(mySet) = [Set]. Use [...mySet].
    • Math.max(arr) = NaN. Use Math.max(...arr).
    • map(id) needs a function: map((e) => e.id).
    • Arrays have push, not append.
    • Reassigning a const throws.
    • A wrong property name gives undefined silently.
    • Variables declared inside { } don't exist outside.
    • None is Python. JS has null.
    DOM gotchas
    • querySelector('agree') looks for an <agree> tag. Ids need #, classes need ..
    • One early error stops everything after it, including later listeners.
    • HTML in JS without quotes is a syntax error; the whole file won't run.
    • A <script src> ignores code between its tags.
    • No 'checkbox' event. Use 'change'.
    • Two listeners toggling the same class cancel out.
    • A listener on a form hears every field's events.
    • form.reset() doesn't fire input/change; reset fires before fields clear.
    • id="reset"/"submit" overwrites form.reset()/form.submit().
    • innerHTML = … wipes everything inside the container.
    • Setting textContent after appending a child deletes the child.
    • A string that looks like HTML isn't an element.
    • closest('tr') also matches header rows; use closest('tbody tr').
    CSS / HTML gotchas
    • No <link rel="stylesheet"> = no CSS.
    • A missing > swallows the next tag.
    • margin: 0 0 1rem also resets the top margin.
    • A rule can lose just by coming earlier in the file.
    • Invalid values are dropped silently (font-weight: 1500, mixed rgb() syntax, outline: 1px).
    • Flex text won't truncate without min-width: 0.
    • for/aria-* references must match ids exactly.
    • class="num" goes on the cell, not the button inside it.
